## งานที่ทำไปทั้งหมด

### 1. Tiered Signal System (hft_paper_run.py — rewrite ใหม่ทั้งหมด)

เปลี่ยนจาก "เข้าครั้งเดียวต่อ window" เป็นระบบ 3 ระดับ เพื่อเพิ่มโอกาสเข้าเทรดโดยไม่เพิ่มความเสี่ยง:

| Tier | EV min | Edge min | Bet size | Max ต่อ window |
|------|--------|----------|----------|----------------|
| STRONG | 2.5% | 4.0% | $1.50 | 3 positions |
| MEDIUM | 0.8% | 1.5% | $0.75 | 2 positions |
| WEAK   | 0.2% | 0.5% | $0.30 | 2 positions |

Max exposure ต่อ window = `3×$1.50 + 2×$0.75 + 2×$0.30 = $6.60 = 6.6%` (cap 10%)

WEAK tier ไม่มี momentum filter → เข้าได้แม้ตลาดนิ่ง แต่ bet เล็กมาก ($0.30)

## ตอบคำถาม: Model นี้ใช้กับตลาดจริงได้ไหม?

### คำตอบสั้น: ได้ — แต่มีเงื่อนไข

**สิ่งที่ระบบนี้ทำได้จริง:**
- ดึงราคาตลาด Polymarket จริง (Gamma API)
- ดึง BTC spot + candle จาก Binance จริง (WebSocket)
- คำนวณ p_model จาก window delta, RSI, momentum, orderbook imbalance
- Kelly sizing ปรับตาม tier bankroll
- ส่ง order ผ่าน py-clob-client ได้ (ถ้ามี MATIC)

**ข้อจำกัดสำคัญที่ต้องรู้:**

| ข้อจำกัด | รายละเอียด |
|---------|-----------|
| PTB proxy ไม่แม่น | Gamma API ไม่ return PTB จริง → ใช้ spot ตอนต้น window แทน ซึ่งอาจคลาดเคลื่อน |
| ราคา YES/NO ไม่ real-time | Gamma refresh ทุก ~10s ไม่ใช่ tick-by-tick |
| TP/SL ไม่ work intra-window | ราคา Polymarket ไม่ขยับระหว่าง window → ต้องรอ settle |
| สภาพคล่องต่ำ | Polymarket BTC market มี spread กว้าง บางครั้ง fill ไม่ได้ |
| Backtest ยังน้อย | ระบบ HFT ใหม่นี้ยังไม่ผ่าน 60-day backtest |

**สรุปความเสี่ยง:** ระบบปลอดภัยพอสำหรับ paper trade และ live ด้วยเงินเล็กน้อย ($8–$20) แต่ยังไม่ควรนำเงินมากเข้าไปจนกว่าจะมีผลลัพธ์ paper trade อย่างน้อย 48–72 ชั่วโมง
