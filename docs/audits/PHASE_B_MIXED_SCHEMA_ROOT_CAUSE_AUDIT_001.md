# PHASE_B_MIXED_SCHEMA_ROOT_CAUSE_AUDIT_001

## Final Verdict

MULTIPLE_WRITERS_DETECTED

## Executive Summary

The mixed schema is caused by two separate runtime writer paths in `polymarket/trader.py` writing to the same `signal_filter_shadow` category through `QuantEventLogger.log_signal_filter_shadow(...)`.

This is not a logger schema translation issue. `QuantEventLogger` preserves the payload fields it receives and only wraps/enriches the event. The schema difference originates before the logger call.

## QuantEventLogger Assessment

`QuantEventLogger` is not translating Phase B rows into old schema.

It:

1. Receives a payload.
2. Adds identity/lineage companion fields where derivable.
3. Wraps the payload under top-level event fields.
4. Writes to the category path.

The old-schema keys `shadow_would_reject` and `shadow_filter_reasons` are not generated by `QuantEventLogger`; they originate in `polymarket/trader.py` legacy shadow block.

Conclusion:

```text
LOGGER_SCHEMA_TRANSLATION = false
```

## Test Coverage Finding

`tests/test_shadow_filters.py` currently preserves both behaviors:

- Legacy tests assert `filter_version == "signal_filter_v1_shadow"` and old fields.
- Phase B tests assert Phase B rows exist when `shadow_telemetry_enabled=True`.

Observed test gap:

```text
No test asserts that enabling Phase B suppresses legacy signal_filter_shadow rows.
```

This allowed runtime to emit both schemas in the same category under the same run_id.

## Root Cause

Root cause:

```text
Phase B telemetry was added as an additional writer, not as a replacement or schema-separated successor for the legacy signal_filter_shadow writer.
```

The runtime currently does:

1. If `settings.shadow_telemetry_enabled`: emit Phase B rows.
2. If `runtime_mode == "paper"`: always emit legacy rows.

Because both use the same logger method and category, enabling Phase B creates mixed schema.

## Minimum Safe Patch Recommendation

Do not implement in this audit.

Minimum behavior-preserving patch:

1. Keep legacy telemetry unchanged when Phase B is disabled.
2. When `settings.shadow_telemetry_enabled == True`, suppress the legacy `signal_filter_v1_shadow` writer or route it to a separate legacy category.
3. Add a regression test:
   - Given paper mode and `shadow_telemetry_enabled=True`
   - Run one approved candidate
   - Assert Phase B rows exist
   - Assert no emitted `signal_filter_shadow` payload has:
     - `filter_version == "signal_filter_v1_shadow"`
     - `shadow_would_reject`
     - `shadow_filter_reasons`
4. Keep live-mode behavior unchanged:
   - live mode emits no legacy or Phase B shadow rows unless separately approved.

Safest smallest code direction:

```python
if self._runtime_mode() == "paper" and not getattr(self.settings, "shadow_telemetry_enabled", False):
    # existing legacy signal_filter_v1_shadow writer
```

Alternative, if legacy telemetry must continue during Phase B:

```text
Route legacy rows to a separate category/name such as signal_filter_shadow_legacy.
```

The first option is smaller and directly satisfies the Phase B smoke gate of no old-schema rows in `signal_filter_shadow`.
