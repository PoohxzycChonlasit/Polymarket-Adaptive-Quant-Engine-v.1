## 8. Improvement Recommendations

### 8a. Log Retention Policy

| Log Type | Location | Current State | Recommended Policy |
|---|---|---|---|
| Application logs | `logs/*.log*` | 556 MB, unbounded | Rotate: keep 14 days, delete older |
| JSONL evidence | `runtime/quant_data/` | 489 MB, 11 days | Archive: keep 30 days live, compress older |
| Realtime CSVs | `runtime/realtime_logs/` | 191 files, 12 days | Keep aligned with JSONL retention |
| Validation logs | `runtime/*.log` | 45 MB, 4 days old | Delete after analysis, not archived |
| Session .err/.out | `runtime/paper_terminal_*.{err,out}` | 1.1 MB, May 7 | Delete after 7 days |

**Implementation:** Add a `tools/log_retention_cleanup.py` script (dry-run by default) that applies the above rules. Do not auto-run from the trading loop.

### 8b. Daily Session Folder Naming

**Current:** `runtime/realtime_logs/YYYY-MM-DD/` (consistent)
**Current:** `runtime/quant_data/*/YYYY-MM-DD.jsonl` (consistent)
**Current:** `docs/research/sessions/YYYY-MM-DD/` (consistent, manual)

**Recommendation:** Standardize session report naming as `{topic}_{YYYY-MM-DD}.md`. This is already followed by the May 18 reports. Enforce in code review.

### 8c. Report Naming Standard

**Current pattern (good):** `{topic}_{YYYY-MM-DD}.md`
Examples: `position_maturity_observation_2026-05-18.md`, `risk_gate_transition_diagnosis_2026-05-18.md`

**Proposed standard:**
```
{category}_{topic}_{YYYY-MM-DD}.md
```
Where category is one of: `diagnosis`, `observation`, `audit`, `replay`, `probe`

This makes grep-by-type easy. Not enforced retroactively.

### 8d. Recovery Backup Policy

Directory `recovery_backups/` is pre-emptively gitignored but does not exist. If used, limit to:
- Max 3 most recent backups
- Content: only config files, never JSONL evidence
- Naming: `{YYYY-MM-DD}_{component}.backup`

### 8e. Obsidian Sync Policy

No automated sync exists or is needed. Manual workflow:
1. Copy finalized `docs/research/sessions/YYYY-MM-DD/` reports to Obsidian vault after each session
2. Obsidian is a read-only consumer of repo docs — it should not write back

### 8f. Hermes Memory Input Policy

`runtime/research_state/latest_research_state.md` is the canonical Hermes input. Rules:
- Update after each significant session (the May 11 version is stale)
- Never commit runtime JSONL as Hermes input
- Keep under 20 KB (current: 18 KB — at limit)

**Recommend:** After each significant session, update `latest_research_state.md` with a 3–5 paragraph diff of what changed, append-only style.

### 8g. Telegram Summary Source Policy
