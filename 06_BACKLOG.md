# 06 Backlog

## Rule

Backlog items are not permission to implement. They are parked until they pass the Profit Filter and receive explicit scope.

## Frozen Backlog

| Item | Status | Resume Only If |
|---|---|---|
| Shadow Strategy Framework adapter expansion | Frozen | Needed to answer a direct profitability or bottleneck question. |
| Large research lab tooling | Frozen | A minimal evidence pipeline cannot answer the question. |
| Inventory ladder runtime | Frozen | Paper wins, TP exits, sizing realism, and market mechanics justify design. |
| New market expansion | Frozen | BTC/ETH 5M has enough profit evidence or clear market-availability ceiling. |
| Strategy threshold tuning | Frozen | Counterfactual plus paper evidence prove a gate is over-conservative. |
| Live pilot | Frozen | Paper profit evidence and live execution readiness are both proven. |
| Dashboard consolidation | Frozen | Operator visibility blocks paper profit validation. |
| Big-bang trader refactor | Frozen | A scoped extraction directly improves safety or profit evidence. |

## Active Candidate Work

| Candidate | Profit Filter Link |
|---|---|
| Entry throughput audit | Entry throughput, expected value, operator visibility. |
| Market-time truth audit | Market reality, execution realism, evidence validity. |
| Paper sizing realism audit | Position sizing reality, live readiness. |

## Backlog Intake Checklist

Before adding work:

1. Name the profit bottleneck.
2. Name the evidence source.
3. Name the files allowed.
4. Name what must not be touched.
5. Define the acceptance criteria.
